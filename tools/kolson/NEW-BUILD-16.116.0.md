## как добавляется NEIZZIR DM (по шагам)

**Ниоткуда не приходит — лежит в библиотеке.** Ни `servers.json`, ни какие-либо
другие источники на этот путь не влияют: DM-сервер — это вкомпилированный
резервный список, и в нём ровно одна запись.

### раскладка блоба

| смещение | размер | что это |
|---|---|---|
| `0x7cc9a..0x7ce9b` | 513 Б | JSON-массив серверов (одна запись — `NEIZZIR DM`) |
| `0x7ce9c..0x7cedb` | 64 Б | дайджест/подпись этого блоба |
| `0x7cedc..0x7cf1b` | 64 Б | ключ, которым проверяются блоб и его сегменты |

### путь исполнения

```
0x29e8e8  загрузчик резервного списка
  0x29e900  x19 = 0x7cc9a                     ; начало JSON
  0x29e910  x0  = 0x7cedc                     ; ключ (64 Б)
  0x29e914  x1  = 0x7ce9c                     ; ожидаемый дайджест (64 Б)
  0x29e91c  x2  = 0x7cc9a, w3 = 0x202         ; блоб и длина (513 + NUL)
  0x29e928  bl  0x1fcbac                      ; проверка целостности -> w0
  0x29e92c  tbz w0, #0, 0x29e970              ; не сошлось -> ветка отказа
  0x29e948  x0 = 0x7cc9a, x1 = 0x7cc9a+0x202  ; диапазон строки
  0x29e954  bl  0x2a0348                      ; разбор JSON (nlohmann)
```

* `0x1fcbac` — общий «проверить блоб» (ключ + данные + длина, внутри аллокация
  `len + 0x40`, т.е. HMAC/подпись с 64-байтовым блоком). Вызывается из трёх
  мест: `0x29be18` (проверка *сегмента* того же JSON — `x3 = end - start`,
  ключ всё тот же `0x7cedc`), `0x29e928` (весь блоб), `0x3a9a04`.
* `0x2a0348` — единственный вызов разбора, вызывается только отсюда.
* `0x29b788` — ленивая инициализация общего объекта списка (guard `0x84d988`,
  флаг «уже разобрали» — `0x84d958`); её вызывают четыре аксессора:
  `0x29df10`, `0x29df5c`, `0x29e080`, `0x29e1d0`.
* загрузчик `0x29e8e8` вызывается из `0x29e7f0`.

То есть запись `NEIZZIR DM` (85.193.87.60:7777, `serverbr`, `featureMask` 1,
живёт до 2027-08-04) появляется в списке тогда, когда лаунчер берёт встроенный
резервный список, а не скачанный `servers.json`; сам список перед разбором
проходит проверку целостности по вкомпилированному ключу.

### если нужно менять этот список

JSON лежит в `.rodata` вместе с ключом и дайджестом, алгоритм проверки
статически вкомпилирован (импортов крипто-библиотек нет), поэтому просто
переписать текст нельзя — проверка не сойдётся. Обходной путь — выключить саму
проверку (2 слова, как в группе `gate` старой сборки):

```
0x1fcbac  0xd503233f (paciasp)              -> 0x52800020 (mov w0, #1)
0x1fcbb0  0xa9ba7bfd (stp x29,x30,[sp,#-0x60]!) -> 0xd65f03c0 (ret)
```

В таблицу `KOLSON_PATCHES_B` это **не** добавлено: `0x1fcbac` проверяет не только
список серверов (ещё два вызова — `0x29be18`, `0x3a9a04`), так что выключать его
стоит осознанно. После этого JSON можно править как обычные данные — длина
блоба при замене должна оставаться 513 байт (дайджест и ключ лежат сразу за ним).
